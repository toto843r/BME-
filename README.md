# بوابة الهندسة الطبية – المرحلة الرابعة

Next.js 14 + Tailwind + Supabase، جاهزة للنشر على Vercel. RTL، وضع داكن، PWA.

## الخطوة 1: إنشاء مشروع Supabase (مجاني)
1. ادخل supabase.com وسجّل بحساب GitHub أو بريدك → **New project**.
2. اختر اسماً وكلمة مرور قوية للقاعدة (احفظها) وأقرب منطقة (مثلاً Frankfurt) → **Create**. انتظر دقيقة.
3. (مشروع جديد فقط) من القائمة اليسرى: **SQL Editor → New query**، افتح ملف `supabase/schema.sql` من المشروع، انسخ كل محتواه والصقه، ثم **Run**. يجب أن تظهر «Success».
4. للتأكد: **Table Editor** فيه جدولان `items` و`reports`، و**Storage** فيه bucket اسمه `materials`.
5. من **Project Settings → API** انسخ:
   - `Project URL`
   - `anon public` key
   - `service_role` key (سرّي، لا تشاركه ولا تضعه في أي مكان عام)

## الخطوة 2: الجدول والسعي
- الجدول في `lib/schedule.ts` (جدول شعبتي A وB الحاليين مدخلان).
- درجات السعي لكل مادة في `lib/assessment.ts` (القياسات الطبية مفصّلة، والباقي 40 بدون تقسيم).
- المواد في `lib/courses.ts`.

ملاحظة عن الجدول: اليوم 0=الأحد … 4=الخميس والوقت بصيغة 24 ساعة (اليوم 0=الأحد … 4=الخميس، والوقت بصيغة 24 ساعة).

## الخطوة 3: رفع المشروع إلى GitHub
1. ادخل github.com → **New repository** (اسم مثل `bme-portal`، Private أو Public).
2. اضغط **uploading an existing file**، اسحب **محتويات** مجلد المشروع (ليس ملف zip نفسه) → **Commit changes**.
   - لا ترفع ملف `.env.local` أبداً.

## الخطوة 4: النشر على Vercel (مجاني)
1. ادخل vercel.com وسجّل بحساب GitHub → **Add New → Project** → اختر المستودع → **Import**.
2. قبل الضغط على Deploy افتح **Environment Variables** وأضف أربعة متغيرات:

| الاسم | القيمة |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Project URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | anon public key |
| `SUPABASE_SERVICE_ROLE_KEY` | service_role key |
| `ADMIN_PIN` | رمز طويل (8 خانات أو أكثر) تختاره أنت |

3. **Deploy**. بعد دقيقتين يظهر لك رابط عام مثل `https://bme-portal.vercel.app`.
4. أي تعديل لاحق على GitHub يُنشر تلقائياً.

## الاستخدام
- **رفع ملف:** صفحة `/upload`. الملفات تدخل حالة `pending`.
- **المشرف:** صفحة `/admin` ثم أدخل `ADMIN_PIN`. من هناك: قبول (مع اختيار الشارات: مهم جداً / مكرر فاينل / ملخص مبسط)، رفض (يحذف الملف من التخزين)، ومعالجة البلاغات.
- **رفعك أنت للمحتوى الرسمي:** ارفعه من `/upload` ثم اقبله من `/admin`.
- **تثبيت التطبيق:** Android/Chrome يظهر زر «تثبيت». iPhone/Safari: زر المشاركة ← «إضافة إلى الشاشة الرئيسية».

## التشغيل المحلي (اختياري)
```
cp .env.example .env.local   # عبّئ القيم
npm install
npm run dev
```

## ملاحظات أمنية
- القراءة العامة تُظهر `approved` فقط (RLS). ملفات `pending` رابطها مخفي لكن الـ bucket عام، فمن يعرف الرابط الكامل يفتحه.
- الرفع العام يمر عبر رابط رفع لمرة واحدة يصدره `/api/upload/sign` بعد فحص الصيغة والحجم (30MB) وبقيود الـ bucket.
- قفل PIN بسيط يُحجب بعد 5 محاولات فاشلة لكل IP (على مستوى النسخة). استخدم PIN طويلاً.
- على iPhone، معاينة PDF داخل النافذة قد تعرض الصفحة الأولى فقط؛ زر «فتح في تبويب جديد» يحل ذلك.

## إضافات النسخة المعدّلة: PWA والاختبارات

### التحديث الآمن
1. احتفظ بالنسخة السابقة وبنسخة احتياطية من قاعدة بيانات Supabase. أنشئ فرع Git جديداً للنشر التجريبي.
2. استبدل ملفات المشروع بهذا المجلد واحتفظ بقيم Environment Variables الحالية كما هي (لا ترفع `.env.local`).
3. افتح Supabase → SQL Editor، ونفّذ **ملف `supabase/quiz_banks.sql` مرة واحدة**. هذا الملف يضيف جدولاً ودالة آمنة دون حذف بيانات `items` أو `reports`.
4. للحصول على التوليد التلقائي، أنشئ مفتاح Gemini API في [Google AI Studio](https://aistudio.google.com/apikey) ضمن **مشروع API في الفئة المجانية بدون ربط Billing**، ثم أضف `GEMINI_API_KEY` إلى Vercel Environment Variables (Production وPreview حسب الحاجة). يمكنك إضافة `GEMINI_MODEL=gemini-3.5-flash-lite`، وتأكد من توفره في منطقتك وحصتك المجانية.
5. نفّذ `npm install` و`npm run build` محلياً أو من خلال Vercel Preview، واختبر قبل نقل التعديل إلى Production.
6. لا تفعل أي Billing مدفوع. انتهاء الحصة أو تعذر التوليد يجعل اختبار الملف غير جاهز مؤقتاً دون محاولة استخدام واجهة مدفوعة.

**توليد الأسئلة:** عند موافقة المشرف على ملف من قسم الملازم (`lectures`) بصيغة PDF، تبدأ محاولة توليد بنك الأسئلة تلقائياً بواسطة جلسة الإدارة؛ وإذا لم تكتمل، يبدأ التوليد آلياً عند أول فتح للاختبار من طالب. تُحفظ 10 MCQ + 10 فراغات + 5 صح وخطأ + 5 تعاريف + 5 تعاليل + 1–2 رسومات إن وجدت؛ لا يعاد طلب النموذج بعد حفظ البنك. الملفات المنشورة سابقاً تُجهّز تلقائياً عند أول فتح لاختبارها، دون تدخل من الإدارة. **لا توجد جدولة شاملة لجميع الملفات القديمة**: يبدأ تجهيز الملف عند أول طلب؛ وذلك لتجنب استهلاك حصة API دفعة واحدة.

**مهم:** التوليد داخل وظيفة Vercel لا يمكن ضمان اكتماله في كل الظروف (انقطاع المتصفح/مهلة الخدمة/حدود Gemini). حالة التوليد محفوظة بقفل على مستوى Supabase؛ يمكن إعادة المحاولة الآمنة بعد 10 دقائق للعملية المعلقة أو 24 ساعة للفشل. لا ننشئ بنوك أسئلة ناقصة إذا فشل التحقق من المخرجات. الأسئلة مُولّدة آلياً وينبغي مراجعتها علمياً قبل الاعتماد عليها في الامتحانات الرسمية.

**الخصوصية:** ملفات الملازم التي يتم توليد الأسئلة منها تُرسل إلى Gemini API. راجع سياسة بيانات الفئة المجانية لملفاتك الأكاديمية قبل التشغيل.

### تفاصيل التصميم
- **Sensors فقط:** يظهر تبويب `امتحانات+` عوضاً عن Quizzes وMidterms؛ البيانات القديمة تبقى في نفس أعمدتها وتعرض معاً. في صفحة الرفع يُحفظ المحتوى الجديد تحت `quizzes` لأجل الحفاظ على توافق مخطط Supabase. بقية المواد لم تتغير أقسامها.
- **آخر الملفات:** شريط تحت السعي (أو فوق أدوات المادة في المختبر)، منفصل لكل مادة ومسار. تُخزن أسماء الملفات وليس محتواها. عند عدم الاتصال بالإنترنت تعرض قائمة الملفات المخبأة فقط.
- **الملفات المتعددة:** نافذة المعاينة تفتح ملفاً واحداً في كل مرة وتتيح التبديل بين المرفقات، مع التحكم بتكبير الصور. لذلك لا تُحمّل جميع ملفات PDF داخل نوافذ iframe في وقت واحد.
- **PWA:** Service Worker صغير خاص بالمشروع دون مكتبات جديدة. يعمل في Production فقط ويخزن HTML والموارد الثابتة والصفحات التي تمت زيارتها (مع قيود للعدد)، ويستثني `/api/` و`/admin` و`/upload` و`/quiz` وملفات PDF. الجدول والقاعات مدخلان أصلاً في `lib/schedule.ts`، ويظهران على الصفحة الرئيسية المحفوظة وفي `/schedule` بعد زيارته.
- **أسئلة Offline:** بعد فتح البنك مرة وهو متصل، يمكن قراءة نسخة منه من تخزين المتصفح؛ إعادة تنزيل محتوى PDF غير مطلوبة.

### قيود معروفة
- لا تضمن الحصص المجانية لـ Gemini أو Supabase أو Vercel سعة غير محدودة. تمنع هذه النسخة التحويل التلقائي إلى AI مدفوع، لكنها لا تضمن مجانية تشغيل مشروع خارجي إذا تجاوزت حصة خطته أو ربطته أنت بخطة مدفوعة.
- لا يمكن ضمان توليد ملف كبير أو ملف ممسوح ضوئياً بجودة مثالية. أقصى حجم ملزمة 30MiB من نظام الرفع الحالي، وقد يتعذر التوليد ضمن حدود الاستجابة والمهلة.
- تختلف طريقة التخزين الآمن لصفحات Next.js RSC؛ لذلك تحفظ الـ PWA واجهة التنقل الأساسية فقط وتترك طلبات `RSC` وAPI دون كاش.
- لم تُعدّل قاعدة بيانات Supabase على حسابك فعلياً في هذه الحزمة؛ يجب تشغيل ملف SQL وإضافة مفتاح Gemini قبل نجاح التوليد على موقعك المنشور.
